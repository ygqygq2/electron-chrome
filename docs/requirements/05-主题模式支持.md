# 05-主题模式支持

## 背景

当前 `electron-chrome` 顶部壳层已经完成浅色浏览器风重构，但主题能力仍是写死的：

- 顶部壳层固定浅色
- 内置 `chrome://settings` 页面固定深色
- 用户无法切换为 `dark / light / system`
- 系统主题变化也不会驱动壳层更新

这会导致“支持系统外观”的基础能力缺失，也让壳层与内置页面在视觉上互相打架。

## 用户故事

- 作为用户，我希望可以明确切换为浅色模式。
- 作为用户，我希望可以明确切换为深色模式。
- 作为用户，我希望可以选择“跟随系统”，让应用随系统明暗变化。
- 作为用户，我希望顶部壳层和内置设置页在同一主题下保持一致，而不是一处浅色一处深色。

## 功能范围

### 本次范围

- 支持三种主题来源：`light`、`dark`、`system`
- 将主题选择持久化到本地用户目录
- 主进程维护主题状态，并将解析后的结果同步到渲染层
- 顶部壳层根据当前主题动态切换样式
- `chrome://settings` 内置页跟随当前主题渲染
- 菜单提供主题切换入口

### 非目标

- 不引入复杂主题编辑器
- 不支持用户自定义主题色
- 不接入远程配置或账户同步
- 不改动网页内容本身的站点主题

## 模块清单

1. 主进程主题状态与持久化
2. 渲染层主题 token 切换
3. 菜单中的主题选择入口
4. 内置设置页主题同步
5. 系统主题监听与自动刷新

## 数据流 / 状态说明

- 用户选择的主题来源由主进程保存为 `themeSource`
- 主进程根据 Electron 原生主题能力计算 `resolvedTheme`
- 渲染层收到状态后，根据 `resolvedTheme` 更新 DOM theme 标记
- 当选择 `system` 时，系统主题变化会触发状态刷新
- 内置设置页重新生成时使用当前解析主题，确保与壳层一致

## 验收标准

- 可以稳定切换 `light / dark / system`
- 关闭并重新打开应用后，主题来源保持不丢失
- `system` 模式下，系统主题变化后壳层可同步更新
- 顶部壳层在深浅模式下都保持可读与层级清晰
- `chrome://settings` 页面与当前主题一致
- `pnpm type-check`、`pnpm lint`、`pnpm stylelint`、`pnpm build` 通过

## 与 video-downloader 的协作关系

- 该主题状态链路可为主项目的浏览器模式提供通用实现参考。
- 若未来主项目需要深浅色统一策略，可复用本次的 Electron 原生主题来源与渲染层 token 切换方案。
