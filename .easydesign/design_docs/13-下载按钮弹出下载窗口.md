# 13-下载按钮弹出下载窗口设计

## 目标

把顶部下载按钮从“原生菜单入口”升级为“真正可用的下载管理窗口”，视觉与交互参考用户提供的系统下载器截图，但不逐像素照搬第三方界面。

## 结构设计

### 入口层

- 顶部工具栏下载按钮点击后直接打开下载窗口
- 菜单里的“下载”入口也统一打开该窗口
- 原先的下载原生菜单不再作为默认路径

### 窗口结构

下载窗口分为三层：

1. 顶部工具栏
   - 标题 / 统计信息
   - 主题切换按钮（参考 `video-downloader` 的 mode toggle）
   - 搜索框
2. 中部列表区
   - 每条下载记录一行
   - 左侧文件类型图标
   - 中间文件名、来源与状态文案
   - 右侧动作按钮
3. 底部操作区
   - 清空已完成
   - 打开下载页
   - 下载设置

## 交互设计

### 列表项状态

每条下载记录需表达以下状态之一：

- 下载中
- 已暂停
- 已完成
- 下载中断
- 已取消
- 文件已删除（完成但磁盘上不存在）

### 列表项动作

- 已完成且文件仍存在：显示“打开”“打开文件夹”
- 文件已删除 / 下载中断 / 已取消：显示“重新下载”
- 非进行中记录：允许删除记录

### 搜索

- 按文件名与来源 URL 做前端过滤
- 输入后即时生效

### 主题切换

- 顶部工具栏右侧增加一个与 `video-downloader` 一致的主题切换按钮
- 按钮本体使用太阳 / 月亮叠层图标，随当前生效主题做过渡切换
- 点击后弹出 3 个选项：`浅色` / `深色` / `跟随系统`
- 选择后直接通过 preload bridge 通知主进程 `setThemeSource`
- 主进程统一刷新壳层内部页与下载窗口，避免出现“主窗口已变色、下载窗口没变”的分裂状态

### 清空已完成

- 仅清理 state=`completed` 的记录
- 不影响下载中 / 中断记录

## 数据设计

主进程维护下载记录快照：

- `id`
- `fileName`
- `sourceUrl`
- `sourcePageUrl`
- `savePath`
- `mimeType`
- `receivedBytes`
- `totalBytes`
- `state`
- `isPaused`
- `canResume`
- `startedAt`
- `updatedAt`
- `existsOnDisk`

窗口通过 preload bridge 获取：

- `getDownloadsState()`
- `onDownloadsStateChanged()`
- `openDownloadsPopup()`
- `openDownloadItem(id)`
- `showDownloadInFolder(id)`
- `retryDownload(id)`
- `clearCompletedDownloads()`
- `removeDownloadRecord(id)`
- `openDownloadsPage()`
- `openDownloadsSettings()`
- `setThemeSource(themeSource)`

## 视觉策略

- 参考系统下载器的“宽列表 + 右侧动作”形式
- 保持浅色背景、大留白和清晰分割线
- 文件名高对比，辅助信息弱化
- 已完成 / 已删除 / 中断状态使用不同语义色
- 整体观感应比原生菜单更像独立桌面工具窗口

## 风险与回退

- 若 Electron `will-download` 未捕获到部分链路，应优先保证正常下载本身不受影响
- 即使窗口无数据，也要保证能正常打开并展示空态
- 若窗口未打开，下载记录也必须在主进程持续积累，待窗口打开后直接展示

## 验证重点

1. 下载按钮点击后是否打开独立窗口
2. 实际下载是否能进入列表
3. 文件删除后状态是否能正确变为“文件已删除”
4. 重新下载是否可触发新下载
5. 浅色 / 深色主题切换时窗口是否同步刷新
6. 下载窗口里的主题按钮样式与交互是否接近参考实现
