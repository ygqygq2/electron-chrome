# 08-浏览器快捷按钮与窗口控制

## 背景

当前 `electron-chrome` 的顶部壳层只有基础导航和菜单按钮，和用户提供的参考图相比，缺少浏览器工具条里常见的快捷操作入口：

- 首页按钮
- 历史记录按钮
- 下载弹出入口
- 扩展入口
- 明确的窗口最小化 / 最大化 / 关闭按钮

这会让顶部工具条仍显得“功能不够像浏览器”，也继续放大之前“连关闭按钮都没有”的问题。

## 用户故事

- 作为用户，我希望能一键回到首页。
- 作为用户，我希望能从顶部快速打开历史记录页。
- 作为用户，我希望能从顶部直接打开下载入口，而不是绕路找菜单。
- 作为用户，我希望能从顶部直接进入扩展页。
- 作为用户，我希望窗口右上角有标准的最小化 / 最大化 / 关闭按钮。

## 功能范围

### 本次范围

- 新增首页按钮
- 新增历史记录按钮
- 新增下载弹出入口
- 新增扩展入口
- 新增窗口最小化 / 最大化 / 关闭按钮
- 收紧标签最大宽度，避免“设置 / 下载 / 扩展”等短标题标签过宽发空
- 为下载 / 扩展提供基础承载（弹出菜单或内置页）
- 主进程同步窗口最大化状态与历史记录入口状态

### 非目标

- 不实现完整下载管理系统
- 不实现真正的扩展安装能力
- 不实现书签同步、账号中心等更多浏览器能力

## 数据流 / 状态说明

- 首页按钮直接导航到默认首页
- 历史记录按钮直接打开 `chrome://history`
- 下载按钮弹出原生菜单，可打开内置下载页
- 扩展按钮打开内置扩展页
- 窗口控制通过 preload bridge 调用主进程执行
- 窗口控制固定放在最上方标签栏的最右侧，而不是地址栏同一排
- 地址栏右侧不再重复回显当前 URL，只在加载中或 DevTools 可见时显示状态文字
- 主进程下发 `isMaximized` 状态，渲染层据此切换最大化 / 还原语义

## 验收标准

- 顶部能稳定看到首页、历史记录、下载、扩展、菜单、窗口控制按钮
- 最小化 / 最大化 / 关闭按钮显示在最上面的标签栏一行右侧
- 当只打开少量标签时，单个标签宽度仍保持克制，不会因为标题短而显得过宽
- 首页按钮点击后能打开默认首页
- 历史记录按钮点击后可直接打开历史记录页
- 下载按钮可弹出下载入口
- 扩展按钮可打开扩展页
- 关闭按钮可直接关闭软件窗口
- `pnpm type-check`、`pnpm lint`、`pnpm stylelint`、`pnpm build` 通过

## 与 video-downloader 的协作关系

- 这套快捷按钮和窗口控制可作为主项目浏览器模式的顶部交互基线。
- 后续若主项目需要“更像桌面浏览器”的壳层，这一轮的按钮分组与状态同步可直接复用。
