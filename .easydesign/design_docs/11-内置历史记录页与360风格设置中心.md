# 11-内置历史记录页与360风格设置中心设计

## 目标

在不引入额外前端框架和复杂路由系统的前提下，为 `electron-chrome` 增加一组更接近真实浏览器的内部页：

- 一个可用的历史记录页
- 一组按分类拆分的 360 风格设置页

## 设计原则

1. **浏览器壳优先**：内部页主要服务于浏览器基础能力验证，不做产品化堆叠。
2. **真实能力优先于假交互**：能接入真实数据的项优先接入，不能接入的明确做只读占位。
3. **仍由主进程生成 HTML**：保持 `electron-chrome` 当前“内置页由主进程模板生成”的架构，避免引入额外 renderer 工程复杂度。
4. **风格参考 360，但不硬抄所有特性**：重点抄信息架构、左侧导航、页面留白和表单组织方式。

## 信息架构

### 历史记录页

页面结构：

- 与设置页共用同款双栏外壳
- 左侧月份 / 日期导航
- 顶部搜索与操作条
- 右侧最近访问列表
- 空状态（若暂无历史）

每条历史记录展示：

- favicon / 站点首字回退
- 页面标题
- 站点域名
- URL
- 访问时间
- 最近访问强调

交互结构参考 `video-downloader/src/pages/history/history-page.tsx`：

- 支持按时间分组显示
- 支持按站点分组显示
- 左侧点击某天后，仅查看当日记录
- 搜索框按标题 / URL 做前端过滤
- 行级 hover 时显示删除按钮与“搜索此网站历史”按钮
- 点击行默认在当前标签打开；Ctrl / 中键可在新标签打开
- 顶部提供“清除所有历史”按钮

### 设置页分类

使用 360 截图中的分类命名作为参考，映射为以下 section：

- browser：基本设置
- uiStyle：界面设置
- tabOptions：标签设置
- downloadSetting：下载设置
- tpMoreMouseGesture：鼠标手势
- shortcut：快捷键
- advanced：高级设置
- lab：实验室
- privacySecurity：隐私安全设置

左侧导航高亮当前 section，右侧主内容只渲染当前 section 对应的设置组。

## 数据模型

### 历史记录

新增历史记录结构：

- `id`
- `url`
- `title`
- `visitedAt`

持久化位置：

- `userData/browser-history.json`

策略：

- 仅记录 `http(s)` 页面
- `did-navigate` / `did-navigate-in-page` 成功后写入
- 按时间倒序展示
- 限制条目总量，避免无限增长

## 主进程实现设计

### URL 解析

扩展内部路由识别：

- `chrome://history`
- `chrome://settings/<section>`

其中设置页保留 `chrome://settings` 作为默认入口，并映射到 `browser`。

### 内置页加载

继续沿用：

- 主进程生成 HTML 字符串
- 包装为 `data:text/html` URL
- `WebContentsView.loadURL()` 加载

新增能力：

- 在内置页中允许跳转到另一个内部 URL
- 主进程拦截内部页内的 `chrome://...` 导航并重写为新的 data URL 页面

## 设置页视觉设计

### 共性布局

- 左侧固定窄导航
- 右侧大面积留白内容区
- 顶部搜索 + 恢复默认设置按钮
- 大量使用轻边框、浅背景、细字体层级

### 当前页内容策略

- `browser`：启动页、搜索、默认浏览器、关闭恢复
- `uiStyle`：主题、工具栏按钮显隐、窗口控制风格说明
- `tabOptions`：新建标签、关闭标签、恢复关闭标签说明
- `downloadSetting`：下载页入口、下载页现状、占位设置
- `tpMoreMouseGesture`：当前未实现，仅说明能力边界
- `shortcut`：展示现有快捷键，如 F5/F12/Ctrl+T/Ctrl+W 等
- `advanced`：GPU 模式、环境标签、兼容模式说明
- `lab`：实验功能说明占位
- `privacySecurity`：历史记录统计、隐私边界说明

## 菜单与入口设计

- `文件` 菜单新增历史记录入口
- `App` 菜单新增历史记录入口
- 地址栏直接输入 `chrome://history` / `chrome://settings/<section>` 可访问

## 风险与回退

### 风险

- 若内部页直接跳转 `chrome://...` 被 Chromium 拦截，可能无法切换 section
- 历史记录若过度写盘，可能造成频繁 I/O
- 内置页模板越写越长，可维护性会下降

### 回退策略

- 若内部导航拦截效果不好，退回为一次性渲染单页设置中心
- 历史记录条目数固定裁剪
- 模板函数继续拆分为 `createHistoryPageHtml()` / `createSettingsPageHtml(section)` 等小函数

## 视觉参考补充

- 直接参考 `video-downloader` 的历史页信息架构与层级：
	- 左侧时间导航
	- 顶部单行搜索 + 分组选项
	- 行级 hover 操作区
- 视觉外壳则直接贴齐 `chrome://settings`：
	- 同样的左侧栏宽度与标题区
	- 同样的顶部搜索 / 操作条节奏
	- 同样的 content block 卡片与留白体系
- 但仍保留 `electron-chrome` 当前“主进程拼 HTML”架构，不引入 React 页面运行时

## 验证重点

1. `chrome://history` 是否可用且能展示真实数据
2. 设置页左侧分类是否可切换并高亮正确 section
3. 浅色 / 深色主题是否保持统一
4. 历史记录与菜单入口是否打通
5. lint / type-check / stylelint 是否通过
