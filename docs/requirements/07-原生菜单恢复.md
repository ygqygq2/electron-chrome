# 07-原生菜单恢复

## 背景

当前 `electron-chrome` 已经有自定义壳层和右侧菜单按钮，但用户仍明确需要把原生菜单栏加回来。

这说明仅靠壳层里的菜单按钮并不能替代桌面端对原生菜单的预期，尤其是在 Linux / Windows 环境下，用户会默认从窗口顶部寻找系统级菜单入口。

## 用户故事

- 作为桌面端用户，我希望应用顶部继续显示原生菜单栏。
- 作为用户，我希望文件、导航、调试、主题这些菜单可以从原生菜单直接访问。
- 作为用户，我希望即使保留自定义壳层，也不要丢掉原生菜单这一桌面软件基础能力。

## 功能范围

### 本次范围

- 恢复并强制显示原生菜单栏
- 保持现有菜单内容：文件 / 导航 / 调试 / 主题
- 继续保留壳层内的菜单按钮，不影响现有自定义入口

### 非目标

- 不移除当前自定义工具栏
- 不重做菜单内容结构
- 不改成完全依赖系统标题栏的传统窗口布局

## 数据流 / 状态说明

- 主进程继续使用 `Menu.setApplicationMenu(...)` 维护全局菜单
- 窗口创建后显式开启 `menuBarVisible`，关闭自动隐藏
- 渲染层不需要为恢复原生菜单增加额外状态

## 验收标准

- 应用窗口顶部能稳定看到原生菜单栏
- 原生菜单项可正常使用
- 自定义壳层与原生菜单可同时存在
- `pnpm type-check`、`pnpm lint`、`pnpm stylelint`、`pnpm build` 通过

## 与 video-downloader 的协作关系

- 该调整验证了“自定义浏览器壳 + 原生菜单并存”的桌面端模式，可为主项目后续窗口层设计提供参考。
