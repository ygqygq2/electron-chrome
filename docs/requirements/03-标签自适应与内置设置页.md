# 03-标签自适应与内置设置页

## 背景

当前 `electron-chrome` 已恢复系统原生菜单栏，但还有三个影响日常使用体验的问题：

1. 最上方系统标题栏额外占掉一条空间，视觉上像“多一层壳”。
2. 原生菜单栏字体与点击区域偏小，单靠系统菜单栏不够顺手。
3. 标签数量增加后，`+` 按钮固定在右侧边缘，不像 Chrome 那样紧跟最后一个可见标签。
4. 顶部按钮风格不统一，像临时拼起来的控件，而不是同一套浏览器壳语言。
5. 浏览器缺少内置设置页，无法像 Chrome 一样在标签页中打开设置。

因此需要在保留系统原生菜单栏的前提下，补上一层更顺手的壳层交互，并让基础内置页面开始成形。

## 用户故事

- 作为用户，我希望顶部有一个更好点的应用菜单入口，而不是只能点很小的系统菜单。
- 作为用户，我希望最顶上的系统标题条消失，让浏览器更像一个整体而不是双层外壳。
- 作为用户，我希望标签越来越多时能自动收缩，而不是把 `+` 号顶到最右边像断层一样。
- 作为用户，我希望后退、前进、刷新、打开、菜单这些按钮属于同一套风格，不要一个像系统按钮、一个像临时 demo 按钮。
- 作为用户，我希望设置可以在标签页里打开，尽量接近 Chrome 的使用习惯。

## 功能范围

### 本次范围

- 壳层增加更大的应用菜单入口
- 隐藏原生系统标题栏显示
- 标签栏改为自适应宽度布局
- `+` 按钮紧跟最后一个可见标签
- 标签标题过长时使用 `...` 截断
- 标签缩到最小宽度后，超出的标签临时隐藏
- 保证可见标签始终保留关闭按钮
- 后退 / 前进 / 刷新 / 打开 / 菜单按钮统一视觉语言
- 支持在标签页中打开 `chrome://settings`
- 设置页提供基础浏览器壳设置入口与说明

### 非目标

- 完整复刻 Chrome 全量设置项
- 书签系统
- 同步账号体系
- 扩展管理
- 复杂的多级设置路由

## 模块清单

1. 标签栏宽度分配与可见窗口计算
2. 应用菜单按钮与原生菜单弹层
3. 原生标题栏隐藏策略
4. 内置页面路由识别
5. `chrome://settings` 页面生成与承载
6. 渲染层标签栏与工具栏样式升级

## 数据流 / 状态说明

- 主进程继续维护 tabs、activeTabId、dockPosition、devtoolsVisible 等核心状态。
- 主窗口隐藏系统标题栏，让顶部只保留菜单栏与浏览器壳本身。
- 渲染层基于窗口宽度和 tab 数量，计算当前可见标签集合与单个标签宽度。
- `+` 按钮位于标签轨道尾部，始终紧跟最后一个可见标签。
- 当用户打开 `chrome://settings` 时，主进程识别为内置页面并渲染本地 HTML 内容，而不是走外部站点加载。
- 应用菜单按钮点击后，通过 IPC 请求主进程在按钮位置弹出原生菜单。
- 渲染层按钮统一使用同一套暗色按钮基线，主操作按钮再叠加蓝色强调样式。

## API / IPC 约定

在现有基础上继续使用：

- `docked-shell:get-state`

- `docked-shell:activate-tab`
- `docked-shell:close-tab`
- `docked-shell:navigate`
- `docked-shell:go-back`

- `docked-shell:show-menu`

## 验收标准

- 顶部出现更大的应用菜单入口，点击后可弹出原生菜单。
- 最上方系统标题栏不再显示，窗口顶部不再出现额外标题条。
- 标签栏中 `+` 按钮紧跟最后一个可见标签，不再固定悬在右边空档处。
- 标签过多时先收缩宽度，再对超出部分进行隐藏。
- 每个可见标签都保留关闭按钮；标题过长时显示 `...`。
- 顶部按钮风格统一，主次操作层级清晰。
- 输入或打开 `chrome://settings` 时，会在当前或新标签中打开内置设置页。
- `pnpm type-check`、`pnpm lint`、`pnpm stylelint`、`pnpm build` 继续通过。

## 与 video-downloader 的协作关系

- 本次改动继续作为 `video-downloader` 浏览器壳能力的前置验证。
- 标签收缩、内置设置页、应用菜单入口等交互若验证稳定，可择机回灌主项目。
