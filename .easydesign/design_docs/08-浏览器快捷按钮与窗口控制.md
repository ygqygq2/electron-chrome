# 08-浏览器快捷按钮与窗口控制设计

## 目标

让顶部壳层更接近桌面浏览器工具条：不仅有地址栏，还要有高频快捷动作和明确的窗口控制区。

## 结构设计

### 左侧导航组

从左到右：

- 后退
- 前进
- 刷新
- 首页

其中首页作为导航组收尾按钮，语义明确。

### 右侧快捷组

从左到右：

- 恢复关闭标签
- 下载入口
- 扩展入口
- 菜单

这样布局更接近用户参考图中的浏览器尾部操作区。

### 顶部窗口控制组

- 最小化 / 最大化 / 关闭 按钮单独挂在最上方标签栏右端
- 不再放在地址栏同一排，避免工具按钮和系统窗口按钮混杂
- 这样更符合“浏览器壳 + 桌面窗口控制”分层，也更接近用户最新截图要求

## 交互设计

### 首页按钮

- 点击后在当前活动标签打开默认首页

### 恢复关闭标签按钮

- 仅在存在最近关闭标签时可点击
- 恢复最近一条关闭记录

### 下载按钮

- 点击后弹出原生菜单
- 菜单可包含：打开下载页、当前无下载项等提示

### 扩展按钮

- 点击后在标签页中打开 `chrome://extensions` 内置页

### 窗口控制按钮

- 最小化
- 最大化 / 还原
- 关闭

关闭 hover 使用风险色，保证识别度。

## 状态设计

渲染层额外感知：

- `canRestoreClosedTab`
- `windowState.isMaximized`

## 页面承载设计

新增内部页：

- `chrome://downloads`
- `chrome://extensions`

第一版允许为轻量占位页，但视觉上要和当前主题保持一致。

## 视觉策略

- 快捷按钮沿用当前浅/深主题按钮体系
- 与导航按钮尺寸统一，但通过图标语义区分用途
- 窗口控制按钮单独成组，并固定在最上方标签栏右侧
- 标签宽度设置明确上限，像“设置 / 下载 / 扩展”这类短标题不会撑成一整块大胶囊
- 状态文字进一步降噪：不再重复显示当前 URL，仅在加载中或 DevTools 可见时临时出现

## 验证重点

1. 按钮分组是否更接近浏览器参考图
2. 高频动作是否都能触发真实行为
3. 关闭按钮是否清晰可见
4. 深浅主题下是否都保持统一
