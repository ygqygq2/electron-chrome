# 02-运行时自适应与壳层美化设计

## 设计目标

在不破坏当前单窗口多标签架构的前提下，完成三件事：

1. 让运行时策略更聪明，但不把长状态提示堆在顶部界面。
2. 让 Linux / WSL 终端输出更干净：压掉已知 Chromium 噪声。
3. 让壳层更像成品：原生菜单、标签栏和地址栏形成统一视觉。

## 运行时策略设计

### 平台检测

主进程在应用启动最前面判断：

- 是否为 Linux
- 是否运行在 WSL
- 是否存在 `/dev/dxg`
- 是否可能需要兼容 GPU 模式

### GPU 模式

定义三类状态：

- `hardware`：默认硬件加速 / 自动模式
- `compatibility`：启动前即判断应走兼容模式
- `limited`：应用启动后检测到 Chromium 对 GPU / WebGL 有限制

### 状态透出

主进程把 `runtimeInfo` 纳入壳状态快照：

```text
runtimeInfo
├─ environmentLabel
├─ gpuMode
├─ gpuLabel
├─ gpuReason
└─ dbusNoiseSuppressed
```

这份状态仍保留在壳状态快照中，便于后续调试或扩展，但当前默认不在顶部显性展示冗长提示。

## dbus / systemd 噪声处理

### 问题

Linux / WSL 下 Chromium 可能输出如下噪声：

- `Failed to call method: org.freedesktop.systemd1.Manager.StartTransientUnit`

该日志对当前产品能力价值低，但会污染开发终端。

### 方案

- 在 Linux / WSL 环境下，对 Chromium 原生日志级别做收敛
- 保留应用自己的 JS / TS 层日志输出
- 不影响主进程真实异常的显式告警

## 菜单设计

### 视觉方案

恢复系统原生菜单栏显示，直接承载 `文件 / 导航 / 调试` 三组命令。

### 交互方案

- 用户通过系统原生菜单栏访问命令
- 菜单项仍由主进程统一构建，快捷键行为保持不变
- 渲染层不再承担菜单入口职责，减少壳层噪声

## 壳层视觉升级

### 结构

壳顶部维持两层可视结构：

1. 标签栏层
2. 地址工具栏层

### 视觉关键词

- 深色、克制、偏原生浏览器
- 更立体但不过分夸张的标签激活态
- 更完整的 URL 栏容器
- 更柔和的边框与阴影
- 标签圆角收敛到 2px，避免过度胶囊化

## 验证重点

1. dev 模式是否仍可正常进入 Electron 窗口
2. GPU 策略是否符合实际运行环境，且顶部不再出现冗长提示
3. dbus 噪声是否不再污染终端
4. 原生菜单栏与快捷键命令是否正确
5. UI 是否达到可展示水准
