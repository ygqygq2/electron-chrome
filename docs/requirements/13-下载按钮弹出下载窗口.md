# 13-下载按钮弹出下载窗口

## 背景

当前 `electron-chrome` 顶部下载按钮点击后仍走原生菜单，只能看到“打开下载页 / 当前暂无下载任务”这类轻量入口，和用户给出的下载管理窗口参考图差距明显：

- 缺少真正的下载任务列表
- 缺少文件名、体积、状态等核心信息
- 缺少打开文件、打开文件夹、重新下载等高频动作
- 缺少“像桌面浏览器/下载器”的独立下载窗口体验

因此需要把下载按钮从“原生菜单入口”升级为“下载管理弹出窗口”。

## 用户故事

- 作为用户，我希望点击顶部下载按钮后，看到一个独立下载窗口，而不是简陋菜单。
- 作为用户，我希望在窗口里直接看到最近下载的文件名、大小、状态和完成情况。
- 作为用户，我希望在下载完成后能直接打开文件或打开所在文件夹。
- 作为用户，我希望当文件已被删除或下载失败时，可以直接重新下载。
- 作为用户，我希望下载窗口视觉上接近系统下载管理器，便于理解和使用。

## 功能范围

### 本次范围

- 顶部下载按钮点击后打开独立下载窗口
- 主进程接入 Electron `will-download` 事件，维护下载记录
- 下载窗口展示：文件名、来源 URL、大小、进度、状态、最近更新时间
- 已完成文件支持“打开”与“打开文件夹”
- 文件已删除 / 下载中断记录支持“重新下载”
- 支持“清空已完成”与搜索下载项
- 主题跟随当前壳层浅色 / 深色模式同步
- 菜单中的“下载”入口与顶部下载按钮行为统一

### 非目标

- 不实现完整下载调度器
- 不实现批量暂停 / 批量继续
- 不实现下载分类、风险扫描、会员加速等业务能力
- 不实现跨重启持久化下载历史（当前先保证本次运行期可用）

## 页面 / 模块清单

- 顶部工具栏下载按钮
- 主进程下载记录管理器
- 下载弹出窗口
- 内置 `chrome://downloads` 下载页（继续保留为补充入口）

## 数据流 / 状态说明

- 页面触发下载时，主进程通过 `session.defaultSession.on('will-download')` 捕获下载项
- 主进程把下载项转换为可序列化的下载记录快照
- 下载窗口通过 preload bridge 拉取并订阅下载记录状态
- 点击“打开 / 打开文件夹 / 重新下载 / 清空已完成”后，回调主进程执行真实文件或下载动作
- 如果文件已从磁盘删除，窗口应明确展示“文件已删除”而不是假装仍可打开

## 验收标准

- 点击顶部下载按钮后，弹出独立下载窗口
- 窗口风格明显比原生菜单更接近用户参考图
- 新下载开始后，窗口可看到实时下载记录
- 下载完成后，可直接打开文件或打开所在文件夹
- 文件不存在时，状态明确显示“文件已删除”
- “重新下载”按钮可重新发起下载
- “清空已完成”只清理已完成记录，不影响进行中的下载
- 浅色 / 深色主题下均保持可读
- `pnpm type-check` 与 `pnpm build` 通过

## 与 video-downloader 的协作关系

- 该下载窗口形态可作为后续主项目浏览器模式的通用下载面板基线
- 后续如果 `video-downloader` 需要承接更强的下载管理能力，可以复用这里的下载记录状态流与窗口交互方式
