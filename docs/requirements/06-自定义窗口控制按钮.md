# 06-自定义窗口控制按钮

## 背景

当前 `electron-chrome` 使用了 `titleBarStyle: hidden` 来去掉系统标题栏，但渲染层没有补齐对应的窗口控制按钮，导致在 Linux/部分桌面环境下，用户看不到明显的软件关闭入口。

这会带来两个直接问题：

1. 用户无法快速发现如何关闭窗口
2. 浏览器壳顶部已经是自定义 UI，却缺少最基本的窗口层交互闭环

## 用户故事

- 作为用户，我希望在应用右上角看到明显的关闭按钮。
- 作为用户，我希望除了关闭外，还能看到最小化和最大化/还原按钮，符合桌面软件直觉。
- 作为用户，我希望这些按钮与当前浅色/深色主题保持一致，不要像临时拼接出来的外挂控件。

## 功能范围

### 本次范围

- 在顶部壳层右上角加入窗口控制区
- 支持最小化
- 支持最大化 / 还原
- 支持关闭窗口
- 按当前主题切换窗口控制按钮视觉
- 主进程将窗口最大化状态同步给渲染层

### 非目标

- 不模拟不同操作系统的全部原生按钮风格
- 不处理多窗口管理面板
- 不实现拖拽吸附、分屏等系统窗口高级能力

## 模块清单

1. 主进程窗口控制 IPC
2. 渲染层窗口控制按钮组
3. 最大化状态同步
4. 浅色/深色按钮样式

## 数据流 / 状态说明

- 渲染层点击窗口按钮后，通过 preload bridge 调用主进程窗口控制方法
- 主进程执行窗口最小化/最大化/关闭
- 主进程把当前 `isMaximized` 状态同步到 shell state
- 渲染层根据 `isMaximized` 切换“最大化 / 还原”图标与提示

## 验收标准

- 顶部右上角能稳定看到关闭按钮
- 最小化 / 最大化 / 关闭按钮都可点击生效
- 最大化后按钮图标或提示能切换为“还原”语义
- 主题切换后，窗口控制按钮风格保持一致
- `pnpm type-check`、`pnpm lint`、`pnpm stylelint`、`pnpm build` 继续通过

## 与 video-downloader 的协作关系

- 该窗口控制方案可为后续主项目浏览器模式提供跨平台壳层控制参考。
- 在采用隐藏标题栏的自定义壳层方案时，可直接复用这套窗口控制 IPC 与状态同步模式。
