# 轻量收藏夹与管理页设计

## 1. 设计目标

在不引入 React 子应用、不破坏当前 Electron Chrome 壳层结构的前提下，补齐最小可用收藏能力：

1. 顶部收藏按钮不再是占位
2. 增加 `chrome://favorites` 内置管理页
3. 收藏数据在主进程统一读写与分发

## 2. 约束

- 当前项目以内置页 HTML + 主进程数据注入为主，不应硬搬 `video-downloader` 的 React 页面
- 收藏能力必须服从“浏览链路优先”，不能影响正常页面导航与承载稳定性
- 避免继续膨胀 `electron/main.ts` 与 `electron/main/page-html.ts`，收藏逻辑应拆入独立模块

## 3. 模块拆分

### 3.1 收藏控制器

文件：`electron/main/favorites-controller.ts`

职责：

- 维护收藏状态
- 处理新增、编辑、删除、移动、创建文件夹
- 对外暴露 `getState()` 与操作方法

### 3.2 收藏页 HTML

文件：`electron/main/favorites-page-html.ts`

职责：

- 生成 `chrome://favorites` 页面 HTML
- 展示文件夹与收藏列表
- 通过 `window.location.href = chrome://favorites/...` 把动作回传给主进程

### 3.3 路由解析

文件：`electron/main/url-utils.ts`

职责：

- 识别 `chrome://favorites`
- 解析新增、编辑、删除、创建文件夹等动作 URL

### 3.4 主进程接线

文件：`electron/main.ts`

职责：

- 创建收藏控制器实例
- 在菜单、工具栏、内部页导航中调用收藏控制器
- 负责刷新已打开的收藏页标签

## 4. 数据流

1. 用户点击收藏夹按钮
2. renderer 请求主进程弹出 `favorites` 菜单
3. 主进程根据收藏状态拼接菜单项
4. 用户选择“收藏当前页”或某条收藏
5. 若是收藏变更，主进程更新本地状态并刷新已打开的收藏页
6. 若是打开收藏，则走当前标签导航或新标签打开

## 5. 页面流

### 5.1 顶部收藏菜单

- 收藏当前页面：地址栏后的星标承担快捷收藏职责，未收藏单击立即落盘；已收藏时以黄色星星展示状态，不再重复弹复杂菜单
- 打开收藏管理页
- 最近更新的若干收藏项

### 5.2 收藏管理页

左侧：

- 文件夹列表
- 新建文件夹
- 收藏当前标签页

右侧：

- 搜索框
- 新建收藏按钮
- 当前文件夹统计
- 收藏列表（打开 / 新标签 / 编辑 / 删除）

## 6. 持久化

文件：`userData/favorites-data.json`

结构：

- `folders: string[]`
- `entries: FavoriteEntry[]`

原因：

- 收藏量通常不大
- 轻量 JSON 已足够
- 与当前历史记录 SQLite 路线不冲突

## 7. 验证点

- `chrome://favorites` 可打开
- 收藏当前页成功落盘
- 相同 URL 重复收藏不会生成脏重复数据
- 收藏页修改后刷新可见
- 重启应用后数据仍在
- 收藏页与历史页、下载页、设置页之间切换无异常
