# 02-运行时自适应与壳层美化

## 背景

当前 `electron-chrome` 已具备基础浏览器壳能力，但在真实 Linux / WSL 开发环境中还存在三类影响体验的问题：

1. GPU 行为缺少自动判断，用户很容易被过长的运行时提示打断注意力。
2. 开发态终端会出现 Chromium / systemd / dbus 噪声日志，干扰排障。
3. 顶部菜单与标签栏仍有偏 demo 的地方，整体观感不够精致。

因此需要在保持当前架构不大改的前提下，补齐运行时自适应能力，并完成第一轮壳层视觉升级。

## 用户故事

- 作为 Linux / WSL 用户，我希望应用能自动判断 GPU 策略，而不是让我手工试开关。
- 作为开发者，我希望终端里不要持续出现无意义的 dbus/systemd 噪声，便于看真正的问题。
- 作为开源项目的使用者，我希望菜单和顶部壳 UI 更完整、更接近可发布产品，而不是脚手架风格。

## 功能范围

### 本次范围

- GPU 运行模式自动判断
- 运行时策略后台自适应，不在主界面显性展示长提示
- Linux / WSL 下 Chromium 噪声日志抑制
- 恢复系统原生菜单栏
- 更完整的标签栏 / 地址栏视觉优化
- 保留原生菜单快捷键与命令定义

### 非目标

- 自定义窗口控制按钮
- 多主题系统
- 下载器业务模块
- 复杂设置页

## 模块清单

1. 主进程运行时环境检测
2. GPU 状态快照与后台策略切换
3. 原生菜单栏与快捷键定义
4. 顶部壳层 UI 重构
5. 设计原型第二版

## 数据流 / 状态说明

- 主进程在应用启动前判断当前平台、WSL 环境、GPU 设备可用性。
- 主进程生成 `runtimeInfo` 并随 `docked-shell:state` 一起广播给渲染层。
- 渲染层仅消费必要壳状态，不直出环境/GPU 长提示，避免顶部信息噪声。
- 原生菜单栏直接承载菜单命令与快捷键，不额外引入自绘菜单入口。

## 验收标准

- `pnpm dev` 启动后，WSL / Linux 的 GPU 策略在后台自动生效，但顶部壳层不展示冗长运行时提示。
- WSL / Linux 下已不再出现该类 dbus 噪声：
  - `Failed to call method: org.freedesktop.systemd1.Manager.StartTransientUnit`
- 系统原生菜单栏恢复可见，快捷键与菜单命令继续可用。
- 整体 UI 明显优于初始化版本，标签栏、地址栏、按钮与状态区更完整，标签圆角保持克制。
- `pnpm type-check`、`pnpm lint`、`pnpm stylelint`、`pnpm build` 继续通过。

## 协作关系

- 本次改动聚焦 `electron-chrome` 自身的运行时体验与壳层观感。
- 后续如方案稳定，可作为其它 Electron 浏览器壳项目的参考实现。
