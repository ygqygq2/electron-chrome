# 04-浅色浏览器壳视觉重构

## 背景

当前 `electron-chrome` 的顶部壳层已经具备基础浏览器能力，但整体仍偏“深色 demo 壳”，与用户提供的参考图相比，存在以下问题：

1. 顶部整体过暗、过厚，像开发者工具条，不像浏览器主界面。
2. 标签、地址栏、按钮之间缺少统一的浅色浏览器语言。
3. 菜单按钮和状态区占位生硬，破坏了浏览器工具栏的连贯感。
4. 当前视觉重心过于集中在深色渐变与大圆角，缺少接近原生浏览器的轻盈感。

因此需要基于现有交互逻辑，对顶部壳层进行一轮“参考图导向”的浅色视觉重构。

## 用户故事

- 作为用户，我希望打开应用时更像一个真正的浏览器，而不是一个深色面板。
- 作为用户，我希望标签区、工具栏、地址栏看起来像同一套浏览器 UI，而不是拼出来的控件。
- 作为用户，我希望顶部更清爽、紧凑，减少压迫感。
- 作为用户，我希望地址栏是视觉中心，按钮退到辅助层，整体更接近参考图中的浅色原生浏览器气质。

## 功能范围

### 本次范围

- 将顶部壳层整体从深色方案切换为浅色浏览器方案
- 重做标签栏、工具栏、地址栏、菜单按钮视觉
- 压缩顶部高度与控件厚度，让布局更紧凑
- 弱化状态区存在感，让地址栏成为视觉核心
- 保留现有交互能力：标签切换、自适应、地址输入、原生菜单弹出、设置页入口

### 非目标

- 不新增书签栏、插件栏、头像区等新功能
- 不改动标签自适应算法
- 不新增下载、收藏、侧边栏等业务能力
- 不完整复刻某个具体浏览器品牌的全部 UI

## 模块清单

1. 浅色标签栏视觉
2. 浅色工具栏与地址栏视觉
3. 菜单按钮/状态区轻量化
4. 顶部整体高度与间距重构
5. 参考图一致性的原型与样式校准

## 数据流 / 状态说明

- 主进程状态流不变，仍由 `dockedShell` bridge 驱动渲染层刷新。
- 本次以渲染层结构与 CSS 视觉重构为主，尽量减少业务逻辑变动。
- 状态区继续显示当前活动标签的轻量状态信息，但视觉降权。

## 验收标准

- 顶部整体观感明显由深色 demo 风转为浅色浏览器风。
- 标签激活态、非激活态、hover 态层级清晰。
- 地址栏成为最主要的视觉焦点，按钮退为辅助控件。
- 顶部高度更紧凑，不再显得厚重。
- 菜单按钮不再突兀，能融入整套工具栏。
- `pnpm type-check`、`pnpm lint`、`pnpm stylelint`、`pnpm build` 继续通过。

## 与 video-downloader 的协作关系

- 本次是浏览器壳“更像真实浏览器”的视觉验证，可为主项目后续壳层统一提供样式语言参考。
- 若该浅色壳层方向验证良好，可作为主项目浏览器模式的视觉基线之一。
